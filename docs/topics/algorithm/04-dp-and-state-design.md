# 动态规划与状态设计

## 1 分钟速答

动态规划最容易把人问崩的点，不是代码，而是状态设计。真正稳定的答法应该先说清 `状态是什么`、`转移从哪里来`、`初始化是什么`、`为什么不会重不漏`。如果这些讲不清，代码大概率只是背过题解。

## 核心机制

### 动态规划在解决什么问题

DP 的本质不是“记忆化搜索”四个字，而是把一个存在重叠子问题和最优子结构的问题拆成可复用状态。

所以面试里最关键的不是“会写表”，而是：

- 你如何定义状态
- 状态之间如何转移
- 为什么这个状态足够描述问题

### 状态设计的常见路径

最常见的思考顺序是：

1. 暴力解怎么写
2. 重复计算出现在哪里
3. 哪个变量决定子问题
4. 这个变量能不能形成状态

举例：

- `爬楼梯`：`dp[i]` 表示到第 `i` 级的方法数
- `打家劫舍`：`dp[i]` 表示前 `i` 个位置的最优解
- `最长递增子序列`：`dp[i]` 表示以 `i` 结尾的 LIS 长度

### 初始化为什么重要

很多 DP 题错不在转移，而在初始化：

- `dp[0]` 表示什么
- 空集 / 空字符串 / 空数组如何定义
- 是否需要多开一位避免边界判断

初始化本质上是在定义递推的起点。

### 自顶向下 vs 自底向上

两种都要会说：

- 自顶向下更贴近问题定义，适合先推导
- 自底向上更适合稳定实现和空间优化

面试里如果先从记忆化搜索说出状态，再落成迭代，通常会更稳。

## 高频问法

- 怎么判断一道题适合动态规划？
- 状态到底该怎么定义？
- 记忆化搜索和 DP 表格法怎么选？
- 空间优化什么时候成立？
- 最长递增子序列为什么还能做到 `O(n log n)`？

## 深挖与误区

- 不要把 DP 回答成“背状态转移公式”
- 不要一上来就写代码，先讲状态和转移
- 不要忽略初始化，它经常决定你递推是否正确
