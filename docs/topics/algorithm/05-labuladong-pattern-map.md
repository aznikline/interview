# 基于本地题单的算法模式地图

## 1 分钟速答

你本地 `labuladong` 元数据里已经有一套很成熟的 `模式 -> 题单` 结构。最有价值的不是把正文搬过来，而是把这些模式分类、题目数量和训练顺序提炼出来，变成你这个仓库里可执行的算法路线。

## 核心机制

### 这份地图在做什么

这不是会员正文的复刻，而是基于本地元数据做的原创整理，重点解决三件事：

- 先练哪些模式，覆盖面最大
- 每个模式大概有多少题，练到什么程度算过线
- 它和当前仓库里的题单、速答包、drill 怎么对应

### 从本地元数据里提炼出的高频模式

下面这些模式是你本地题单里最有代表性的主线：

| 模式 | 本地题量 | 为什么先练 |
| --- | ---: | --- |
| 链表双指针 | 18 | 训练指针移动、链表基本功和边界处理 |
| 数组双指针 | 27 | 高频、覆盖广，很多题都能回收成相向或快慢指针 |
| 前缀和 | 11 | 区间和、子数组、计数类题的核心基础 |
| 差分数组 | 3 | 题量不大，但特别适合面试里体现“批量更新”的抽象能力 |

| 二分搜索 | 19 | 不只是查值，更重要的是单调性和边界思维 |
| 栈 / 队列 | 36 | 题量大、套路固定，单调栈和辅助队列都常考 |
| 二叉树相关 | 12-22 | 二叉树遍历、分解问题、层序思维是算法面试核心 |
| 哈希表 | 15 | 频次、去重、映射、前缀状态统计的底层工具 |
| 堆 | 15 | top k、流式最值、优先级调度高频出现 |
| Trie | 8 | 搜索建议、前缀匹配和字符串字典类题常见 |
| 图遍历 / 并查集 | 6 / 10 | 连通性、拓扑、集合合并是图题主干 |
| 最短路 | 5 | 题量不大，但一旦问到就很拉开差距 |
| DFS / 回溯 | 24 / 21 | 枚举空间、剪枝、路径构造是必会能力 |
| BFS | 22 | 层级最短步数和状态扩展的关键方法 |
| 经典 DP | 19 | 最值、计数、状态设计的主阵地 |
| 游戏 DP | 18 | 区间、博弈、状态轮换类进阶题 |
| 贪心 | 8 | 常和 DP、二分答案形成对比 |
| 数学技巧 | 23 | 面试中经常拿来做变体和补充 |

### Quick Master 视角更像“面试冲刺版”

你本地元数据里还有一组更适合冲刺的 `quick_master` 分类。它比 `beginner` 更短、更偏模式压缩：

- 链表双指针、递归链表
- 数组双指针、二维数组
- 滑动窗口、二分搜索
- 前缀和 / 差分
- 栈、队列、单调栈、单调队列
- 二叉树、BST
- 图、DFS / 回溯、BFS
- 动态规划、贪心、分治、数学

这组结构特别适合你当前仓库的 `速答包 + 口述训练` 模式。

### 一条推荐学习顺序

按覆盖面和迁移性，建议顺序是：

1. 数组双指针
2. 滑动窗口
3. 二分搜索
4. 前缀和 / 差分
5. 栈 / 单调栈 / 单调队列
6. 二叉树遍历与分解
7. 图遍历 / 并查集 / BFS
8. DFS / 回溯
9. 经典 DP
10. 贪心、分治、数学补漏

这条线和你仓库里现有的 [算法核心题清单](/Users/wizout/op/interview/questions/algorithm/00-must-know.md) 是一致的，只是现在更明确了“按什么顺序刷模式”。

- 为什么 DP 放在后面更稳？

## 深挖与误区

- 不要把题量多理解成必须全刷完，重点是先拿下模式迁移能力
- 不要只盯难题，算法面试真正稳定的是高频模式的口述能力
- 不要把这份地图当目录，必须配合题单、速答包和每日 drill 去跑
