# 算法的框架、例题和训练法

## 1 分钟速答

算法准备不能只做题。更高效的方法是把内容拆成三层：`框架` 负责识别模式，`例题` 负责建立直觉，`训练` 负责把思路说顺和写稳。

## 核心机制

### 为什么算法内容要按“框架 -> 例题 -> 训练”组织

只刷题很容易出现两个问题：

- 看过很多题，但换皮就不会
- 会写代码，但开口讲不清思路

所以这个仓库把算法准备拆成三步：

1. 先学框架：知道滑动窗口、双指针、二叉树遍历、回溯、DP、图算法分别适合什么问题
2. 再做例题：用代表题把框架落下来
3. 再做训练：口述思路、复杂度、边界条件和变体追问

### 一套建议顺序

1. 数组与字符串
2. 双指针 / 滑动窗口
3. 栈与单调结构
4. 二叉树 / 图搜索
5. 回溯
6. 动态规划
7. 并查集 / 拓扑 / 最短路

### 每个框架最少要练到什么程度

对于每个模式，至少要做到：

- 能说出 `适用条件`
- 能说出 `标准模板`
- 能举出 `1 道代表题`
- 能指出 `2 个常见坑`

## 高频问法

- 什么题一眼看出来适合滑动窗口？
- 双指针和滑动窗口怎么区分？
- DFS、BFS、回溯的边界在哪？
- DP 怎么从暴力推导出来？
- 单调栈为什么能把复杂度降下来？

## 深挖与误区

### 误区 1：只背代码模板

模板只是起点。真正决定你能不能过面试的是：看到题后能不能解释“为什么这个模板适合这里”。

### 误区 2：只做，不讲

算法面试不是 OJ。你必须能在落笔前先说出：

- 状态怎么定义
- 指针怎么移动
- 为什么不会漏解
- 复杂度是多少

### 误区 3：忽略边界条件

很多人刷题时依赖调试，但面试里必须主动讲出：

- 空数组 / 空树
- 重复元素
- 下标越界
- 初始化状态
