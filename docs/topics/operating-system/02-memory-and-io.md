# 内存与 I/O

## 1 分钟速答

OS 里的内存与 I/O 是后端性能题的底层根因来源。你需要能把虚拟内存、页表、TLB、缺页异常、多路复用、零拷贝和 mmap 连到真实延迟与吞吐问题上，而不是停留在定义层。

## 核心机制

### 内存链路

- 虚拟地址需要经过页表映射到物理地址
- TLB 缓存热点映射
- 缺页异常会触发内核介入
- 页替换与 NUMA 都会影响延迟

### I/O 链路

- 用户态通过系统调用进入内核
- 数据在设备、内核缓冲区、用户缓冲区之间移动
- 多次拷贝和上下文切换会放大开销

### 零拷贝与 mmap

- 零拷贝目标是减少 CPU 拷贝与上下文切换
- `mmap` 让文件映射到进程地址空间，适合特定读写模式

## 高频问法

- 为什么 page fault 会导致请求抖动？
- sendfile 为什么比普通 read/write 更高效？
- mmap 和普通文件 I/O 各自适合什么场景？

## 深挖与误区

- 零拷贝并不总是“完全没有拷贝”
- mmap 不适用于所有大文件处理场景
- 性能问题不能只怪 GC 或代码，内核行为经常是真正瓶颈
