# MySQL 事务与锁

## 1 分钟速答

MySQL 事务题的核心是两条线：`一致性怎么保证` 和 `并发下如何控制冲突`。前者要讲 redo log、undo log、MVCC，后者要讲行锁、间隙锁、next-key lock 和隔离级别。面试里不能只背 ACID，要把读写冲突与真实业务问题连起来。

## 核心机制

### 事务原子性与持久性

- `undo log` 用于回滚，支撑原子性
- `redo log` 用于崩溃恢复，支撑持久性
- `binlog` 主要用于复制与归档，不等同于 redo log

### MVCC

- 一致性读依赖 `Read View`
- 每行记录隐含版本信息
- 通过 undo log 链回溯历史版本
- 在可重复读下，普通 `select` 不加锁但能看到一致快照

### 锁模型

- 行锁保护具体记录
- 间隙锁保护区间，防止幻读
- next-key lock = 行锁 + 间隙锁
- 意向锁用于表级协调，不是“更重的业务锁”

## 高频问法

- MVCC 解决了什么，没解决什么？
- 可重复读为什么还能防幻读？
- 为什么唯一索引和非唯一索引加锁行为不同？
- MySQL 死锁是怎么发生的？如何排查？

## 深挖与误区

- MVCC 不是万能的，当前读仍然会加锁
- `select for update` 和普通 `select` 的语义完全不同
- binlog / redo log / undo log 的职责不要混淆
