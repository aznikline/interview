# 消息队列可靠性与幂等

## 1 分钟速答

MQ 题核心是四件事：`为什么要异步`、`怎么保证不丢`、`怎么接受重复`、`怎么处理顺序与积压`。只会说“削峰填谷”还不够，面试官更想听的是投递语义和业务补偿方案。

## 核心机制

### 为什么用 MQ

- 异步解耦
- 削峰
- 广播与多订阅
- 失败重试与延迟处理

### 可靠性链路

- 生产者确认
- Broker 持久化与副本复制
- 消费者 ack / offset 提交
- 重试队列、死信队列、监控告警

### 幂等与顺序

- 至少一次天然带来重复消费
- 业务幂等通常通过唯一键、状态机或去重表实现
- 分区顺序通常能做，全局顺序代价高

## 高频问法

- 至少一次、至多一次、恰好一次分别意味着什么？
- 为什么顺序性和吞吐量经常冲突？
- 消息积压怎么处理？
- 事务消息适合什么场景？

## 深挖与误区

- 面试里不要承诺“绝不丢消息”，要先定义故障边界
- 幂等不是 MQ 提供就万事大吉，最终落在业务状态设计上
- 顺序消费常常牺牲扩展性和吞吐
