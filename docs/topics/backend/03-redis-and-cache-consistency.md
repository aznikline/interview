# Redis 与缓存一致性

## 1 分钟速答

Redis 面试最容易回答空。真正的重点不是“快”，而是缓存何时命中、何时失效、何时重建，以及它和数据库在一致性、过期、热点、故障下怎么协同。缓存的价值永远和业务模式绑定。

## 核心机制

### Redis 为什么快

- 内存访问
- 单线程命令执行减少竞争
- I/O 多路复用
- 面向场景优化的数据结构

### 一致性模型

- `Cache Aside` 是最常见方案
- 读路径：cache miss -> DB -> 回填缓存
- 写路径：更新 DB -> 删除缓存
- 更高一致性要求可用 CDC / binlog 驱动缓存刷新

### 常见缓存问题

- 穿透：查不存在的数据
- 击穿：热点 key 失效瞬间打到 DB
- 雪崩：大量 key 同时失效或实例故障
- 热 key：单 key 过热造成单点压力

## 高频问法

- 为什么写 DB 后通常选择删缓存而不是更新缓存？
- 延迟双删解决了什么，没解决什么？
- 热 key 和大 key 如何治理？
- Redis 持久化为什么会影响延迟？

## 深挖与误区

- “用 Redis 提升性能”不是答案，必须给出命中率与链路收益
- 缓存一致性没有银弹，面试重点是业务可接受窗口
- 不要忽略缓存重建成本与热点转移
