# 后端基础总览

## 1 分钟速答

后端面试的核心不在于背概念，而在于你是否能把 `并发`、`存储`、`通信`、`一致性`、`故障处理` 五条线连起来。多数高频题都可以映射到这五类问题：请求怎么进来、数据怎么存、缓存怎么协同、异步怎么解耦、异常怎么兜底。

## 核心机制

### 并发与隔离

- 线程、协程、事件循环决定并发模型
- 锁、CAS、事务、幂等决定共享状态如何被安全修改
- 线程池、连接池决定资源如何被复用

### 存储与索引

- MySQL 关注：事务、隔离级别、索引、锁、日志
- Redis 关注：单线程模型、数据结构、持久化、淘汰策略
- MQ 关注：削峰、解耦、重试、幂等、顺序性

### 分布式一致性

- 缓存与数据库的双写一致性
- 消息投递的至少一次与重复消费
- 分布式锁与时钟问题
- 服务调用中的超时、重试与雪崩

## 高频问法

- MySQL 为什么用 B+ 树而不是哈希索引作为通用主索引？
- Redis 为什么快？快的边界在哪里？
- 缓存击穿、穿透、雪崩分别是什么？
- 如何设计一个高并发下单系统？
- 消息队列如何保证不丢消息？
- 分布式事务在业务里怎么落地？

## 深挖与误区

- 不要把“用了 Redis”当成高性能答案，关键是命中率、更新策略和一致性成本
- 不要把“加锁”当成并发问题通用解，锁会带来竞争、死锁和吞吐下降
- 不要孤立讲组件，要讲组件在完整链路中的角色与 trade-off
