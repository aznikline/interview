# 缓存一致性与流量治理

## 1 分钟速答

系统设计里的缓存不是一个独立组件，而是吞吐、延迟和一致性之间的平衡器。只要用了缓存，就必须回答数据源是谁、何时失效、何时重建、异常如何兜底，以及高流量下如何防穿透、击穿和雪崩。

## 核心机制

### 一致性问题

- 数据库为真源
- 写路径常用更新 DB 后删缓存
- CDC / MQ 可用于异步刷新
- 多级缓存要考虑失效顺序

### 流量治理

- 限流：令牌桶、漏桶、滑动窗口
- 降级：兜底数据、静态页、默认推荐
- 预热：热点 key 预加载
- 隔离：读写分离、热点拆分

## 高频问法

- 缓存一致性和最终一致性如何结合？
- 热点 key 为什么会拖垮整个链路？
- 限流应该做在网关、应用还是下游？

## 深挖与误区

- 缓存方案必须配合过期、监控和重建策略
- 限流不能只靠单点计数，分布式场景要考虑一致性成本
- 不要忽略回源风暴
