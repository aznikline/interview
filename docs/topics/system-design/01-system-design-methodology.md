# 系统设计方法论

## 1 分钟速答

系统设计面试本质上考察你如何在不完美信息下做工程决策。标准流程不是直接画组件图，而是先澄清需求，再做容量估算，再决定数据模型与核心链路，最后讨论扩展性、一致性和容错。

## 核心机制

### 先把问题拆对

- 功能需求：系统必须做什么
- 非功能需求：QPS、延迟、可用性、数据一致性、成本
- 边界：是否跨地域、多租户、强一致还是最终一致

### 再把架构搭对

- 接入层：API Gateway、限流、鉴权
- 计算层：服务拆分、同步 / 异步链路
- 存储层：读写模式、索引、冷热分层
- 缓存层：命中率、一致性策略
- 异步层：MQ、延迟任务、重试

## 高频问法

- 设计短链接系统
- 设计 Feed 流系统
- 设计秒杀系统
- 设计消息队列
- 设计分布式唯一 ID

## 深挖与误区

- 没有容量估算的设计容易变成空谈
- 只讲“上 Redis”和“上 MQ”没有意义，必须说明为什么上、代价是什么
- 设计题需要取舍，不存在所有指标都最优的方案
