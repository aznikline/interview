# 秒杀与高并发设计

## 1 分钟速答

秒杀系统设计不只是“扛高并发”，而是同时处理 `流量洪峰`、`库存正确性`、`链路削峰` 和 `最终一致性`。一旦没有明确边界，系统不是被打爆，就是超卖。

## 核心机制

### 入口削峰

- CDN、静态化
- 排队、验证码、抢购令牌
- 频控、防刷、黑名单

### 核心链路

- 预扣库存或资格校验前移
- 下单异步化，通过 MQ 削峰
- 订单、库存、支付走状态机与补偿

### 一致性与可观测

- 防重复下单
- 库存回补
- 超时取消
- 成功率、排队长度、下单耗时监控

## 高频问法

- 预扣库存为什么不是最终答案？
- 一人一单如何防作弊？
- 秒杀失败用户体验如何设计？

## 深挖与误区

- “Redis 扣库存”不是完整方案，必须回答持久化确认
- 系统可用性和公平性经常冲突
- 高并发场景下，排队成功不等于订单成功
