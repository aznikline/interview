# 系统设计 14 天计划

适合：

- 已经知道一些组件，但系统设计答题没有主线
- 想在两周内把代表题讲到“能过一面和二面”
- 目标是看到题先识别场景，再讲约束和 trade-off

## 使用原则

- 每天只练 `1` 个场景，不求全
- 每天至少做：`需求澄清 -> 粗估算 -> 核心链路 -> 瓶颈与恢复`
- 每天口述一遍，不只看文档

## Day 1：总框架

- 看 [系统设计答题法](/Users/wizout/op/interview/docs/guides/how-to-approach-system-design.md)
- 练 `需求 -> 估算 -> 架构 -> 瓶颈 -> trade-off -> 故障`

输出：

- 2 分钟讲完整体框架

## Day 2：短链接

- 练编码、冲突、热点、过期

输出：

- 说清短码生成和热点读优化

## Day 3：秒杀

- 练削峰、限流、库存保护、补偿

输出：

- 说清为什么高并发不是“上 Redis 就完了”

## Day 4：Feed 流

- 练 fanout on write / read / hybrid

输出：

- 说清普通用户和大 V 的不同策略

## Day 5：消息队列

- 练分区、顺序、消费组、积压

输出：

- 说清消息系统在系统设计里的角色

## Day 6：全局唯一 ID

- 练号段、Snowflake、回拨风险

输出：

- 说清唯一性和有序性的取舍

## Day 7：搜索建议

- 练前缀检索、排序、热门词、个性化

输出：

- 说清为什么这题不只是 Trie

## Day 8：容量估算专项

- 专门练 QPS、存储、带宽、对象大小

输出：

- 至少能对 3 道题快速做一版估算

## Day 9：缓存与热点

- 练缓存层次、热点分布、降级

输出：

- 说清缓存是为了什么，不是为了“看起来高级”

## Day 10：异步与一致性

- 练为什么上 MQ、为什么不用强一致

输出：

- 说清异步和一致性的取舍

## Day 11：限流、降级、熔断

- 练资源保护和优先级

输出：

- 说清至少 2 层限流和 2 个降级动作

## Day 12：恢复与预热

- 练恢复期放量、缓存预热、积压回放

输出：

- 说清为什么恢复阶段也会再次打崩系统

## Day 13：完整串讲

- 从代表题里任选 2 道，按完整结构口述

输出：

- 每道题 5-8 分钟版本

## Day 14：压测与复盘

- 跑 [系统设计压测包](/Users/wizout/op/interview/practice/drills/system-design-pressure-pack.md)
- 做一次 mock

输出：

- 一页纸系统设计弱项清单

## 最小验收标准

- 至少 `6` 道代表题能讲顺
- 每道题都有粗估算
- 被追问时能补限流、恢复和 trade-off
