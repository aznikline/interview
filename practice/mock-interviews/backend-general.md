# Mock 1：通用后端

## 场景设定

3-5 年后端工程师，参与过高并发交易或内容系统。

## 问题序列

1. 讲一个你做过的核心项目。
2. Redis 为什么快？你们怎么用？
3. 缓存与数据库双写不一致怎么解决？
4. MySQL 索引为什么用 B+ 树？
5. 设计一个秒杀系统。
6. 为什么 epoll 比 select 更适合高并发？

## 追问脚本

- 如果缓存删除失败怎么办？
- 为什么高并发系统里还会慢？
- 你的项目里哪些指标最重要？
- 如果库存错了，如何补偿？

## 评分维度

- 结论是否先行
- 是否能讲出底层原理
- 是否有工程取舍
- 是否能联系真实项目

## 参考答案

每道题先压缩成 1 分钟答法，再展开到 3-5 分钟。回答项目时一定覆盖：

- 背景与目标
- 约束
- 方案
- 结果指标
- 复盘
