# Mock 3：资深后端

## 场景设定

5-8 年后端工程师，做过高并发核心链路或基础架构优化。

## 问题序列

1. 讲一个你真正做过并能体现 trade-off 的项目。
2. 为什么更新数据库后删缓存通常比更新缓存更稳？
3. MVCC 和锁在你项目里的问题排查中是怎么体现的？
4. 如果线上 MQ 积压并且订单延迟暴涨，你怎么处理？
5. 设计一个全局唯一 ID 系统。
6. 你如何做限流、降级和容量评估？

## 追问脚本

- 你的方案里哪个地方最脆弱？
- 有没有一次事故改变了你的设计？
- 为什么没选另一种方案？

## 评分维度

- 是否能从指标和故障说话
- 是否能表达 trade-off
- 是否能把原理和业务现场对应起来

## 参考答案

资深面试最忌讳“只讲组件不讲判断”。每道题都尽量补：

- 约束
- 代价
- 失败场景
- 观测指标
