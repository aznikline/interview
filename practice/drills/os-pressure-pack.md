# OS 压测包

适合：

- 概念知道，但一问到真实服务现象就乱
- 主问题能答，追问到指标、代价和缓解就空
- 想把 OS 题练成“机制 -> 现象 -> 指标 -> 缓解”的稳定结构

## 使用方法

- 每次只选 `1` 个主问题
- 主问题答 `1` 分钟，再接 `3` 轮追问
- 每轮都强制回到 `机制 / 现象 / 指标 / 缓解`

## Section 1：线程切换与吞吐

### 主问题

线程切换为什么贵？

### 第一轮追问

- 到底保存恢复了什么？
- 为什么 cache 和 TLB 会被打散？
- 线程多为什么不一定更快？

### 第二轮追问

- 协程为什么通常更轻？
- 用户态线程和内核线程差别在哪？
- 上下文切换高时先看什么指标？

### 第三轮追问

- 如果 CPU 很高但吞吐很低，你怎么判断是不是切换问题？
- 如果面试官继续追问线程池大小和调度，你先讲哪层？
- 如何一句话解释“线程不是越多越好”？
