# 追问压测包

适合：

- 速答能答出来，但一追问就开始发散
- 知识点看过很多，临场承压不稳定
- 想把“会答”推进到“被连续追问还能稳住”

## 使用方法

- 每轮选 `1` 个主问题，不要一口气全刷
- 主问题先答 `1` 分钟，再连续接 `3` 轮追问
- 每轮追问只给自己 `20-30` 秒组织，再直接说
- 如果第三轮已经开始胡扯，立刻停下复盘，不要硬顶

## Section 1：后端与一致性

### 主问题

为什么很多业务不用强一致分布式事务？

### 第一轮追问

- 那你会怎么选 `2PC / TCC / SAGA / 本地消息表`？
- 为什么这里不用 TCC？
- 如果下游部分成功了，怎么补偿？

### 第二轮追问

- 补偿失败怎么办？
- 为什么只靠重试不够？
- 对账应该按什么维度做？

### 第三轮追问

- 如果业务方坚持“必须不能错”，你怎么重新界定一致性目标？
- 如果补偿和对账都很贵，哪里先做轻，哪里必须做重？
- 面试官继续追问到幂等键和唯一约束时，你怎么收回主线？

### 答稳最低要求

- 先说一致性目标，不先堆协议名
- 每一轮都能落回 `代价 / 侵入性 / 兜底` 三个点
- 至少举一个订单、库存、权益或通知类业务场景

## Section 2：系统设计与恢复

### 主问题

为什么系统恢复阶段也可能出现第二次事故？

### 第一轮追问

- 缓存恢复时为什么会回源打爆数据库？
- MQ 恢复消费时为什么会压死下游？
- 为什么不能恢复后立刻全量放开？

### 第二轮追问

- 预热一般怎么做？
- 平滑放量是按用户、按流量还是按功能开关？
- 如果核心链路和非核心链路抢资源，先保谁？

### 第三轮追问

- 如果业务方要求“先全部恢复再说”，你怎么解释风险？
- 如果恢复后 P99 还是很差，你先看哪几个指标？
- 如果已经发生二次事故，复盘里最该补哪层？

### 答稳最低要求

- 每一轮都能补 `限流 / 降级 / 恢复策略`
- 能明确说出一个监控指标和一个恢复动作
- 不把恢复讲成“服务起来就结束”

## Section 3：算法与变体

### 主问题

为什么这题是动态规划，而不是贪心或搜索？

### 第一轮追问

- 你的状态为什么这样定义？
- 如果换一种状态会怎样？
- 初始化最容易错在哪里？

### 第二轮追问

- 什么时候能做空间优化？
- 为什么 01 背包要倒序？
- 这题如果面试官改成变体，你先改状态还是改转移？

### 第三轮追问

- 如果你现场一时想不到最优做法，怎么保住分数？
- 如果面试官追问到 `O(n log n)` 版本，你怎么解释而不乱？
- 怎么把这题从“会写”讲到“会解释为什么对”？

### 答稳最低要求

- 不先写代码，先讲模式和状态
- 每轮都能回到 `状态 / 转移 / 初始化 / 复杂度`
- 至少能指出一个边界条件和一个常见坑

## Section 4：OS 与性能现象

### 主问题

为什么服务已经用了 epoll，还是会被慢请求拖垮？

### 第一轮追问

- epoll 到底解决了什么，没解决什么？
- 为什么线程池和下游依赖仍然是瓶颈？
- 零拷贝能不能解决这个问题？

### 第二轮追问

- 慢连接和慢 SQL 各自怎么拖垮服务？
- 如果 CPU 很高但吞吐上不去，你先怀疑什么？
- 上下文切换和 cache miss 会怎么放大问题？

### 第三轮追问

- 如果面试官继续追问 Reactor、线程模型和超时控制，你怎么接？
- 如果已经出现尾延迟恶化，你先看哪些指标？
- 如果需要一句话解释“为什么 epoll 不是银弹”，你怎么说？

### 答稳最低要求

- 每轮都能分清 `就绪发现` 和 `业务处理`
- 能说出至少一个系统指标和一个缓解动作
- 不把 OS 题答成单纯 API 定义

## Section 5：AI 编译器与 Runtime

### 主问题

为什么 runtime 不能完全替代编译优化？

### 第一轮追问

- 哪些优化必须在 compile time 做？
- 哪些决策应该留到 runtime？
- dynamic shape 为什么会逼着 runtime 介入？

### 第二轮追问

- 融合为什么有时平均更快但 P99 更差？
- decode 为什么常 memory bound？
- layout 变化为什么会影响 kernel 表现？

### 第三轮追问

- 如果面试官让你在 `IR / pass / kernel / runtime` 里选一个展开，你选哪层最稳？
- 如果你没有完整 compiler 项目，怎么把这题讲得可信？
- 如果指标冲突，比如吞吐更高但 TTFT 更差，你怎么取舍？

### 答稳最低要求

- 每轮都能回到 `层次边界 / 瓶颈 / 指标`
- 至少能说出一个 compile-time 决策和一个 runtime 决策
- 不把回答讲成框架名罗列

## 复盘问题

- 我最容易在哪一轮开始散？
- 我是不是一被追问就忘了原来的主问题？
- 我有没有把答案拉回代价、边界和指标？
- 下次我应该补哪份题集、专题或 mock？
