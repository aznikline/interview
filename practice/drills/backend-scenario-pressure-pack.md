# 后端场景压测包

适合：

- 组件题会答，但一到业务场景就开始漂
- 第一问能答，第二问追到失败和恢复就虚
- 想把后端题练成“链路定位 + 取舍 + 兜底”

## 使用方法

- 每次只选 `1` 个主场景
- 主问题答 `1` 分钟，再接 `3` 轮追问
- 每轮都强制回到 `链路位置 / 代价 / 兜底 / 指标`

## Section 1：缓存一致性

### 主问题

为什么通常删缓存，而不是直接更新缓存？

### 第一轮追问

- 为什么先删再写库不稳？
- 延迟双删到底在补什么洞？
- 为什么 binlog / CDC 常被拉进来？

### 第二轮追问

- 如果删除缓存失败怎么办？
- 如果缓存已经被旧值重建怎么办？
- 什么场景下你反而会直接更新缓存？

### 第三轮追问

- 如果业务方要求“不能有脏读”，你怎么重新定义目标？
- 如果缓存挂了，系统怎么退化？
- 如果面试官继续追问热点和大 key，你怎么切回主线？

## Section 2：消息与积压

### 主问题

消息积压了，你怎么处理？

### 第一轮追问

- 先看哪些指标？
- 是生产过快、消费过慢，还是下游故障？
- 扩容为什么不一定立刻生效？

### 第二轮追问

- 顺序消费积压怎么办？
- 死信队列是解决问题还是延后问题？
- 哪些消息可以降级丢弃？

### 第三轮追问

- 如果恢复消费后数据库被打崩怎么办？
- 如果业务方要求“绝对不能丢”，你怎么讲代价？
- 如果继续追问到幂等和重试边界，你怎么接？

## Section 3：一致性与补偿

### 主问题

为什么很多业务不用强一致事务？

### 第一轮追问

- 2PC、TCC、SAGA、本地消息表怎么选？
- 什么场景下 TCC 侵入太大？
- 什么场景更适合本地消息表？

### 第二轮追问

- 补偿失败怎么办？
- 对账为什么经常是最后兜底？
- 只靠重试为什么不够？

### 第三轮追问

- 如果业务方坚持“必须不能错”，你怎么解释代价？
- 如果系统已经部分成功，最先保护哪个状态？
- 如果面试官追问到幂等键和唯一约束，你怎么讲清边界？

## Section 4：高并发与恢复

### 主问题

为什么恢复期也可能把系统再次打崩？

### 第一轮追问

- 缓存恢复为什么会回源打爆 DB？
- MQ 恢复为什么会压死下游？
- 为什么不能瞬间全量放开？

### 第二轮追问

- 预热一般怎么做？
- 平滑放量按什么维度切？
- 核心链路和非核心链路先保谁？

### 第三轮追问

- 如果恢复后 P99 还是很差，先看什么？
- 如果已经发生二次事故，复盘最该补哪层？
- 如果业务方只关心恢复速度，你怎么讲风险？

## Section 5：锁、ID 与状态机

### 主问题

为什么分布式锁经常不是最优解？

### 第一轮追问

- 锁在解决什么问题？
- 为什么唯一约束和状态机更稳？
- Redis 锁最常见的坑是什么？

### 第二轮追问

- GC 停顿和锁超时会带来什么风险？
- Redlock 的争议点是什么？
- 什么场景下你仍然会用分布式锁？

### 第三轮追问

- 如果面试官把问题改成全局 ID 或去重，你怎么切模式？
- 如何一句话解释“锁把问题转成了锁服务正确性问题”？
- 如果被追问时钟回拨和状态机边界，你先展开哪层？

## 复盘问题

- 我最容易在哪个场景里漂掉主线？
- 我有没有把方案讲成“组件列表”，而不是业务链路？
- 我是不是忘了补指标、代价和恢复动作？
- 下一轮我该补哪组代表题或专题？
