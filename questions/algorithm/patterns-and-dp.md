# 算法进阶题

## 题目

什么样的问题适合滑动窗口？

## 一句话回答

当问题对象是连续区间，并且窗口在扩张或收缩时能维护某种约束或统计量时，通常适合滑动窗口。

## 展开回答

- 典型特征是“子串 / 子数组 / 连续区间”
- 窗口状态可增量维护，如字符频次、区间和、distinct 数
- 若窗口不满足条件，就通过左指针收缩恢复合法状态
- 关键在于“合法窗口定义”而不是双指针本身

- 如果窗口条件不单调还能用滑窗吗？
- 最短覆盖子串为什么更难？

## 题目

动态规划题最关键的三步是什么？

## 一句话回答

状态定义、转移方程和初始化是 DP 的三大核心，其中状态定义决定了整道题能不能写对。

## 展开回答

- 状态定义：这个子问题到底表示什么
- 转移方程：当前状态如何由更小子问题得到
- 初始化：边界条件和 base case
- 完成后再考虑遍历顺序与空间优化

## 题目

并查集的路径压缩和按秩合并为什么有效？

## 一句话回答

路径压缩让查找时把节点直接挂到根上，按秩合并避免树退化，两者结合使均摊复杂度接近常数。

## 展开回答

- 查找时递归回溯顺便压平路径
- 合并时总让浅树挂深树
- 树高被持续压低，因此后续操作更快
- 常用于连通性、冗余边、朋友圈等问题

- 并查集能处理删除边吗？
- 并查集和 DFS/BFS 连通性判断如何取舍？

## 题目

为什么很多二叉树题最终都能写成 DFS 模板？

## 一句话回答

因为树天然是递归结构，很多问题都可以表示为“当前节点答案依赖左右子树答案”，这正适合 DFS 后序或前序框架。

## 展开回答

- 前序适合自顶向下传递约束
- 后序适合自底向上汇总信息
- 面试时先判断信息流方向，再选 DFS 位置
- 中序在 BST 类问题里尤其自然

## 面试官追问

- 路径和类问题为什么常用前序？
- 直径 / 高度类问题为什么常用后序？
- 什么时候 BFS 更自然？

## 题目

动态规划里的“状态”到底怎么设计？

## 一句话回答

状态设计的关键不是套模板，而是找到“哪些变量足以唯一描述一个子问题”。如果状态信息不够，会漏情况；如果状态过重，复杂度会爆炸。

## 展开回答

- 从暴力解出发，先看重复计算到底重复在哪
- 把真正决定子问题结果的变量提炼成状态
- 判断状态是否同时满足“可转移”和“可复用”
- 设计状态时要同步考虑初始化、遍历顺序和空间复杂度
- 面试里最好先口述 `状态含义 -> 转移来源 -> base case`

## 题目

什么时候可以做 DP 空间优化？为什么滚动数组容易写错？

## 一句话回答

当当前状态只依赖有限的前置状态，且这些依赖不会被当前轮覆盖时，才适合做空间优化。滚动数组容易错，是因为更新顺序一旦破坏原始依赖，状态就被污染了。

## 展开回答

- 先看 `dp[i]` 只依赖 `dp[i-1]` 还是依赖整行/整列
- 若只依赖上一层，可把二维压成一维
- 01 背包常要倒序遍历，完全背包常是正序，原因在于是否允许重复使用当前轮状态
- 优化空间前要先把未优化版本写稳，否则很难定位错在哪里
