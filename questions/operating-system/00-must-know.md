# 操作系统核心题清单

## 题目

后端面试里的操作系统最该准备哪些题，顺序应该怎么排？

## 一句话回答

优先准备最能解释性能和并发现象的题：`进程线程 -> 上下文切换 -> 虚拟内存 -> I/O 模型 -> 多路复用 -> 零拷贝 -> 锁与内存模型`。顺序上先抓“现象背后的机制”，再抓“和服务性能的关系”。

## 展开回答

### 第一层：必须会讲的基础机制

- 进程和线程区别是什么？
- 线程切换为什么贵？
- 用户态和内核态如何切换？
- 虚拟内存解决了什么问题？
- page fault 为什么会导致抖动？
- select / poll / epoll 区别是什么？
- zero-copy / sendfile / mmap 是什么？
- 死锁为什么发生？如何避免？
- false sharing 是什么？
- 内存屏障为什么重要？

### 第二层：必须能连到工程现象

这些问题不能只背定义，必须能联系到服务问题：

- 为什么高并发服务会被上下文切换拖垮
- 为什么 epoll 服务仍然可能被慢请求拖慢
- 为什么 page fault 和缓存 miss 会放大尾延迟
- 为什么锁竞争和 false sharing 都会让 CPU 很忙但吞吐上不去

### 第三层：建议刷题顺序

1. 先看 [操作系统专题首页](../../docs/topics/operating-system/00-index.md)
2. 再看 [OS 核心](../../docs/topics/operating-system/01-os-core.md)
3. 再看 [内存与 I/O](../../docs/topics/operating-system/02-memory-and-io.md)
4. 再看 [并发与调度](../../docs/topics/operating-system/03-concurrency-and-scheduling.md)
5. 然后刷 [OS 高频题](high-frequency.md)
6. 最后刷 [并发与内存题](concurrency-and-memory.md)

### 第四层：最小交付标准

每类问题至少要做到：

- 讲清“它是什么”
- 讲清“为什么会有它”
- 讲清“它影响了什么性能或并发现象”
- 讲清“工程里如何观察和缓解”

### 1 分钟速答表

| 题目 | 最低合格回答 |
| --- | --- |
| 进程和线程区别是什么？ | 进程是资源隔离单位，线程是调度执行单位；线程切换轻一些，但共享地址空间也更容易带来并发问题。 |
| 线程切换为什么贵？ | 因为要保存恢复上下文，还会打散 cache 和 TLB，切换过多时吞吐会明显掉。 |
| 用户态和内核态如何切换？ | 通过系统调用、中断、异常进入内核，代价不只是一条指令，而是整个权限和上下文切换。 |
| 虚拟内存解决了什么？ | 它把地址空间抽象出来，解决隔离、扩展和按需分配问题，但 page fault 和缺页换入会带来抖动。 |
| select / poll / epoll 最大差别是什么？ | 前两者每次都要扫集合，epoll 把关注和就绪拆开，更适合大量连接下找出真正值得处理的 fd。 |
| 零拷贝是什么？ | 主要是减少用户态和内核态之间不必要的数据搬运，不是完全零成本，协议处理和网络开销还在。 |
| 死锁为什么发生？ | 资源互斥、请求保持、不可剥夺、循环等待同时成立时就可能死锁，规避靠破坏其中一个条件。 |
| false sharing 是什么？ | 多线程改的是不同变量，但落在同一 cache line 上，导致一致性同步频繁，CPU 忙但吞吐上不去。 |
| 内存屏障为什么重要？ | 因为编译器和 CPU 会重排序，没有内存序约束就很难保证多线程可见性和先后关系。 |
| 为什么 epoll 服务也会慢？ | epoll 只解决就绪发现效率，不会让业务逻辑、线程池和下游调用自动变快。 |

### 最小合格回答标准

如果你只想把 OS 题先答到不失分，至少做到：

- 每题都能先说“影响了什么现象”，不要只背教材定义
- 能补一个观测手段，比如上下文切换、CPU、页缺失、尾延迟
- 能把机制连到服务问题，比如慢请求、锁竞争、吞吐下降
- 被追问时至少能继续讲 `代价 / 瓶颈 / 缓解方式`

## 面试官追问

- 为什么 epoll 服务还会被慢请求拖垮？
- 协程为什么不是万能方案？
- 锁竞争和 false sharing 有什么区别？
- page fault、TLB miss、cache miss 谁更贵？
- 零拷贝为什么不是完全零成本？

## 易错点

- 只会教材定义
- 不会结合真实服务
- 不会讲系统层开销
- 把内核机制和业务现象割裂开
