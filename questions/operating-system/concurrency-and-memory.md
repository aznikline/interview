# 操作系统进阶题

## 题目

线程切换为什么贵？

## 一句话回答

线程切换虽然比进程切换轻，但仍要保存和恢复寄存器、调度状态、栈上下文，还可能引发 cache miss 和 TLB 失效，因此频繁切换会明显降低吞吐。

## 展开回答

- 调度器需要做上下文保存与恢复
- 不同线程工作集不同，容易打散 CPU cache
- 锁竞争会让线程频繁阻塞与唤醒
- I/O 密集场景中线程过多经常适得其反

## 题目

epoll 为什么适合高并发连接？

## 一句话回答

因为 epoll 把“注册感兴趣的 fd”和“返回已就绪的 fd”分开处理，避免每次都线性扫描全部连接。

## 展开回答

- `select/poll` 每次调用都要遍历整个 fd 集合
- epoll 维护就绪事件队列
- 连接很多、活跃连接少时收益更明显
- 但最终性能仍取决于业务处理和系统资源

## 题目

为什么会发生 false sharing？

## 一句话回答

因为不同线程修改了位于同一 cache line 的不同变量，导致缓存一致性协议频繁失效和同步，从而出现性能下降。

## 展开回答

- cache line 是一致性同步的最小粒度
- 即使变量逻辑上独立，只要物理上落在同一 cache line 就会互相影响
- 在高并发计数器、队列头尾指针等场景很常见
- 常见优化是 padding、对齐或重新布局数据结构

## 题目

内存屏障为什么重要？

## 一句话回答

因为 CPU 和编译器都会做重排序，内存屏障用来约束可见性和执行顺序，保证并发程序符合预期。

## 展开回答

- 单线程语义正确不代表多线程可见性正确
- acquire / release 屏障帮助建立 happens-before
- 锁、原子变量底层都离不开内存序语义
- 面试里重点是“为什么需要”，不是背指令名

- CAS 为什么还需要内存序？

## 题目

为什么用了 epoll，服务还是可能被慢请求拖垮？

## 一句话回答

因为 epoll 只优化了“发现谁就绪了”的效率，不负责让业务逻辑变快。如果线程池阻塞、下游响应慢、请求体过大或连接长期占用资源，服务照样会被拖垮。

## 展开回答

- epoll 解决的是高并发连接下的事件分发，不是业务执行时间
- 应用层若同步调用下游，仍会把工作线程卡死
- 慢客户端、慢磁盘、慢数据库都会把尾延迟放大
- 真正稳定的答案要同时讲 I/O 模型、线程模型、超时和限流

## 题目

零拷贝到底减少了什么成本？为什么它不是银弹？

## 一句话回答

零拷贝主要减少内核态和用户态之间不必要的数据搬运与上下文切换，但它并没有消除协议处理、校验、排队、磁盘和网络本身的成本，所以只能优化链路中的一部分。

## 展开回答

- `sendfile` 能减少用户态 buffer 参与的数据 copy
- `mmap` 能减少显式 read/write 的数据搬运
- DMA 参与后，CPU 在大文件分发中的压力会下降
- 但业务逻辑加工、压缩加密、协议封装仍然可能要求数据进用户态
- 因此零拷贝更适合静态文件传输、日志回放这类直通型场景
