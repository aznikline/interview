# 系统设计高频题

## 题目

如何设计一个短链接系统？

## 一句话回答

短链接系统的核心是长短映射、跳转高可用和读多写少场景下的缓存设计，同时要处理冲突、过期、统计和恶意流量。

## 展开回答

- 写路径：生成短码，写入映射表，处理去重与过期时间
- 读路径：短码解析，优先查缓存，命中后跳转原始 URL
- 数据模型：`code -> long_url / expire_at / owner / metadata`
- 生成策略：自增 ID + base62，或随机生成 + 冲突检测
- 扩展点：点击统计、地域分析、风控、CDN、热点缓存

## 面试官追问

- 为什么很多方案偏向自增 ID + 编码？
- 热门短链如何避免单点热点？
- 如何防止恶意短链和钓鱼链接？

## 题目

如何设计一个秒杀系统？

## 一句话回答

秒杀系统的关键不是“卖出去”，而是在高并发下保证限流、库存正确、链路削峰和最终一致。

## 展开回答

- 流量入口先做静态化、CDN、限流和验证码
- 库存校验尽量前移到 Redis 或内存层，但最终以数据库或持久层校验为准
- 下单链路异步化，通过 MQ 削峰
- 订单、支付、库存回补走最终一致性补偿
- 重点要说明“能承受多大流量”和“超卖如何避免”

- Redis 预扣库存的风险是什么？
- 一人一单怎么做得足够稳？

## 题目

如何设计一个消息队列？

## 一句话回答

消息队列设计要平衡吞吐、顺序、可靠性和可扩展性，核心涉及写入日志、消费位点、分区、副本和重试机制。

## 展开回答

- 写入模型通常是顺序追加日志，提升吞吐
- 分区实现水平扩展，但会影响全局顺序
- 消费者通过 offset 或 ack 管理位点
- 副本复制保证高可用
- 重试、死信、幂等保证消费健壮性

- RocketMQ 为什么适合更复杂业务语义？
