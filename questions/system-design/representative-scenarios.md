# 系统设计代表题清单

## 题目

如果只保最值得练的一批系统设计题，应该怎么选？

## 一句话回答

先保最能覆盖 `高频读、写洪峰、时间线、异步、全局 ID、检索、恢复治理` 七类场景的题。不是题目越多越好，而是每道题都要能讲清 `约束 -> 架构 -> 瓶颈 -> trade-off -> 故障处理`。

## 展开回答

### 一组推荐代表题

| 场景 | 推荐代表题 | 你要练什么 |
| --- | --- | --- |
| 高频读跳转 | 短链接、搜索建议 | 热点、缓存、编码、过期、降级 |
| 高并发写入 | 秒杀、下单链路 | 削峰、库存保护、异步化、补偿 |
| 时间线聚合 | Feed 流、通知中心 | fanout 取舍、混排、回补 |
| 异步解耦 | 消息队列、状态流转 | 分区、顺序、积压、重试、消费组 |
| 标识与路由 | 全局唯一 ID、短码、分片键 | 唯一性、有序性、热点和路由 |
| 检索与排序 | 搜索建议、检索结果页 | 索引、排序、个性化、更新链路 |
| 恢复治理 | 缓存挂了怎么办、恢复期放量怎么做 | 限流、降级、预热、灰度、监控阈值 |

### 最小刷题路径

如果你时间很少，先保下面这 `8` 题：

- 设计短链接系统
- 设计秒杀系统
- 设计 Feed 流
- 设计消息队列
- 设计全局唯一 ID 系统
- 设计搜索建议系统
- 为什么容量估算不能省略？
- 为什么恢复期也可能再次打崩系统？

### 每题最低输出标准

每道题至少要能说出：

- 需求澄清
- 一版粗估算
- 核心链路
- 一个瓶颈点
- 一个 trade-off
- 一个故障处理动作

## 面试官追问

- 为什么这题需要缓存？
- 为什么这题要上 MQ？
- 为什么这里不用强一致？
- 如果流量翻十倍先动哪层？
- 如果缓存或 MQ 挂了，怎么退化？

## 易错点

- 一上来画组件图，不先澄清需求
- 没有容量估算，架构选择像拍脑袋
- 只会讲主链路，不会讲瓶颈和恢复
