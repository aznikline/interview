# 后端代表题清单

## 题目

如果只保最值得讲的一批后端题，应该怎么选？

## 一句话回答

先保最能串成完整链路的场景题：写链路、缓存、消息、一致性、高并发、恢复和排障。每组不要贪多，但必须能从“是什么”讲到“为什么这样选”和“失败怎么办”。

## 展开回答

### 一组推荐代表题

| 场景 | 推荐代表题 | 你要练什么 |
| --- | --- | --- |
| 写链路与事务 | MySQL 为什么用 B+ 树、MVCC 解决了什么、redo/undo/binlog 区别 | 存储结构、事务机制、读写并发 |
| 缓存与热点 | Redis 为什么快、缓存穿透/击穿/雪崩、为什么删缓存 | 热点治理、一致性窗口、故障退化 |
| 消息与异步 | MQ 如何保证消息不丢、消息积压怎么办、顺序消息如何取舍 | 削峰、解耦、ack / 重试 / 死信 |
| 一致性与补偿 | 2PC/TCC/SAGA 怎么选、补偿和幂等怎么配、为什么不用强一致 | 取舍、侵入性、兜底 |
| 高并发 | 秒杀 / 下单链路、限流降级、恢复期放量 | 资源保护、链路优先级、恢复策略 |
| 锁与状态机 | 分布式锁为什么不是最优解、幂等和状态机怎么落地 | 去重、串行化、状态流转 |
| 排障与复盘 | 热 key、大 key、慢查询、消息积压、慢请求怎么排 | 指标、观测、止血顺序 |

### 最小刷题路径

如果你时间很少，先保下面这 `12` 题：

- MySQL 为什么用 B+ 树？
- MVCC 解决了什么？
- Redis 为什么快？边界在哪里？
- 缓存穿透、击穿、雪崩怎么治理？
- 为什么通常删缓存而不是更新缓存？
- MQ 如何保证消息不丢？
- 至少一次为什么会带来重复消费？
- 消息积压了怎么办？
- 为什么很多业务不用强一致事务？
- 2PC / TCC / SAGA / 本地消息表怎么选？
- 分布式锁为什么经常不是最优解？
- 为什么恢复期也会再次打崩系统？

### 每题最低输出标准

每道题至少要能说出：

- 它位于业务链路的哪一段
- 它在解决什么资源或一致性问题
- 一个失败场景
- 一个兜底动作

## 面试官追问

- 为什么不直接更新缓存？
- 为什么不直接上分布式锁？
- 为什么一定要用 MQ？
- 如果恢复后 P99 仍然很差，先看什么？
- 如果业务坚持强一致，你怎么重新界定代价？

## 易错点

- 只会背概念，不会讲链路位置
- 只讲方案，不讲代价和边界
- 故障题没有观测指标和恢复动作
